# Lane C Dogfood — Week 3 port, first live run

Date: 2026-04-15
Run: `kg extract-decisions` on the two real Phase-0 docs (`design.md`, `ceo-plans/org-memory-os.md`) after `kg init` + `kg import` on a fresh throwaway vault at `/tmp/lane-c-dogfood/vault/`.

This is a **production-adjacent** smoke test of the week-3 port. Eval harness measures recall against a curated 10-gold subset per doc; dogfood surfaces what happens on the full (uncurated) extraction cap.

## What worked

- **End-to-end wiring is clean.** `kg init → import → extract-decisions` ran without code changes. 15 Decision nodes + 15 `decided_in` edges landed on design.md's first run. Frontmatter includes `extractor: lane-c-v1.1`, `source_line`, and `extractor_reasoning` per the materialize contract.
- **Deterministic-id dedup is correct when inputs match.** Re-run on `design.md` skipped 6 items whose extracted text was byte-identical to the first run.
- **decided_in edges reach SQLite** (status: `nodes: 27 edges: 25`, one edge per Decision).
- **Source-doc validation works.** Attempting to extract from an un-imported file is rejected with a clear error.
- **15 tests green**, full suite 149/150 pass post-port.

## What surfaced (real issues)

### 1. Precision cliff at cap=15 (expected in hindsight; now observed)

On design.md's first run, ~6 of 15 extracted items are **non-decisions** by the v1.1 dataset gold labels:

- `"로컬 퍼스트 vs 클라우드 퍼스트 … Git 기반 동기화가 첫 후보"` — gold `n001`
- `"과금 모델: 팀당 월 구독 vs AI 토큰 사용량 기반. 유저 10명 확보 후 결정."` — gold `n003`
- `"인터뷰 검증 게이트: AI 네이티브 팀 리더 5명 …"` — metric/gate (n011 pattern)
- `"외부 유저 확장 월 6: 10명의 AI 네이티브 팀 리더 …"` — goal (n007 pattern)
- `"PMF 시그널 월 12: 유기적 유저 증가 매월 30% …"` — metric (n010 pattern)
- `"1주일 안에 AI 에이전트를 팀에서 일상적으로 쓰는 사람 5명에게 직접 연락해서 30분씩 인터뷰"` — action item, not recorded commitment

Precision ≈ 60% on full design-doc extraction. Eval harness never exposed this because it only checks recall against a gold subset and discounts unmatched extractions as "coverage-unknown" (see `eval/scripts/eval-extract.mjs` header).

**Implication for MVP**: Raw extractor output is too noisy to feed unfiltered into the graph. Two viable mitigations:

- **Classify-as-postfilter**: pipe each extracted item through `classifyDecision` (P=1.000 R=0.971) before materializing. Drop `non_decision`. Adds ~15 extra LLM calls per doc but CLASSIFY is cheap (≤200 tokens).
- **Tighten EXTRACT prompt** on goals/metrics/action-items (known weaknesses — `BREADTH OVER DEPTH` rule is already there; needs reinforcement on the "not a decision" side).

### 2. Extractor non-determinism even at temperature=0

Re-running on the identical doc produced:
- Run 1: 15 items
- Run 2: 16 items, 10 of which had text not seen in Run 1

`temperature=0` stabilizes aggregate metrics (recall 0.900 reproducible on 2-doc eval) but does NOT guarantee byte-identical text between runs. My idempotency strategy — deterministic id from `sha256(sourceDocId|normalizedText)` — only dedupes identical text. Re-runs on the same doc therefore create ~2/3 new Decision nodes.

**Implication**: "same doc, same result" is false today. Options:
- Accept drift; mark the latest extraction as canonical via metadata (`run_id`).
- Add text-similarity dedup (embedding cosine ≥ threshold) before materialize.
- Use classify as a gate and accept the occasional near-duplicate.

### 3. Filename bloat

Longest decision filename: 163 bytes (Korean UTF-8 is 3 bytes/char, so ≈55 chars plus date prefix and slug punctuation). Approaches the 255-byte filesystem limit. `titleFromText` caps title at 80 chars, but `slugify` doesn't further cap the slug.

Fix: add a post-slug byte-length cap (e.g. 100 bytes → truncate + hash-suffix) in `defaultPathForType`. Low-risk, local change to `src/graph/write.ts`.

### 4. VERBATIM rule drift

Decision #1 text: `"AI 에이전트 네이티브 워크스페이스 접근 선택 — Notion 킬러가 아닌 새 카테고리"`.
Source doc line 79: `"AI 에이전트가 first-class 참여자인 지식+업무 그래프. Notion 킬러가 아닌 새 카테고리. …"`.
Source doc line for d001 gold: `"Approach C: 에이전트 네이티브 워크스페이스 ← CHOSEN"`.

The extractor **paraphrased** by combining tokens from multiple lines. The VERBATIM rule in the prompt is not enforced against long-form paraphrase; the model fabricates a "title-style" summary when the actual verbatim decision line is short. Also the claimed `line: 155` is a frontmatter closing marker in a code-block example — a hallucinated anchor.

Fix direction: strengthen the VERBATIM section with a "reject any text that does not appear as a contiguous token sequence in the source" clause, and probably add post-hoc validation (substring-check extracted text against the body; drop if no match).

## Recommended next steps (ordered by ROI)

1. **Classify-as-postfilter in `materializeDecisions`** (or in a new `extractAndFilter` layer). Gates on the V2 classifier's `decision`/`non_decision` label. Biggest precision win with smallest code change.
2. **Filename byte cap + hash suffix** in `src/graph/write.ts`. Safety fix against long Korean titles.
3. **VERBATIM post-check** in `extract.ts`: drop extracted items whose normalized text isn't a substring of the body's normalized text. Cheap, local, catches hallucinations.
4. **Text-similarity dedup** (embedding cosine) for idempotent re-runs. Requires embeddings to already be backfilled; defer until real usage shows pain.
5. **Re-run EXTRACT v1.1 eval with classify-postfilter baked in** to quantify the precision improvement and confirm no recall regression.
